## 目標

提供一個簡單 web UI，讓操作者可以：

1. 手動切換 virtual inputs：
   - part_present（workpiece present）
   - fixture_clamped
   - welder_ready
   - safety_gate_closed（注意：此 input 會觸發 Protective Stop 邏輯）

2. 即時看到這些 inputs 如何影響：
   - CabinetState（READY / WAITING / RUNNING / ESTOP / PROTECTIVE_STOP / FAULT）
   - Status Light（red / yellow / green）
   - cycle_running（true / false）
   - 最近一次 job 結果（last_job_result）

3. 保持 virtual_only 模式，不改動任何真實 I/O 或 hardware。

   - 顯示最近一次 completed job 的結果（若存在）。

2. 後端：
   - 新增或擴展現有 API route，例如：
     - GET  /api/v1/virtual_inputs
     - POST /api/v1/virtual_inputs
   - POST body 範例：
     {
       "part_present": true,
       "fixture_clamped": false,
       "welder_ready": true,
       "safety_gate_closed": true
     }
   - 呼叫現有 VirtualControllerCabinet.set_input() 或等效邏輯，確保：
     - safety_gate_closed=False 觸發 PROTECTIVE_STOP

3. 與現有 virtual controller 整合：
   - 使用現有 virtual_controller_cabinet.py 的 set_input() 或等效方法。
   - 確保 WAITING 狀態的 readiness re-evaluation 仍然正確。
   - 確保 completed job result retention 仍然正確。

4. 安全與限制：
   - 明確在 UI 上標示：此為 virtual demo panel，不接真實 I/O。
   - 不允許從這個 panel 直接觸發 E‑Stop、Fault 或 Protective Stop；這些仍應由現有 safety 邏輯或現有 UI 控制。

## 八、修正 Drag、上移、下移沒有功能

目前 Drag、上移及下移沒有作用，必須修正，不是刪除這些控制項。

### Drag

- 使用 Drag handle 可拖曳調整已顯示欄位的排列。
- 拖曳後，版面設定中的列順序同步更新。
- 變更納入待儲存的版面設定。

### 上移／下移

- 按上移，該已顯示欄位向前移動一個位置。
- 按下移，該已顯示欄位向後移動一個位置。
- 第一個可移動欄位的上移按鈕應停用。
- 最後一個可移動欄位的下移按鈕應停用。
- TxId 不再因舊的固定顯示規則而被鎖定移動；已顯示時按相同排序機制處理。

### 保留的欄位排列規則

Visible = true：
- 按用戶設定的 display_order 排列。
- Drag／上移／下移只改欄位在 List 從左至右的顯示次序。
- 不改資料行排序方向。

Visible = false：
- 不按 display_order 排列。
- 按欄位名稱升序排列。
- 不套用已顯示欄位的手動移動次序。

由 visible = false 改為 true：
- 自動放在最後一個已顯示欄位之後。
- 不插入原本已顯示欄位中間。
- 用戶之後可再透過 Drag／上下移動調整位置。

### 儲存與取消

- Drag／上下移動後，按「儲存」才持久保存並套用到 List。
- 未儲存的排列不可提前影響 List。
- 儲存後重新載入，次序仍然一致。
- 按「取消」復原至原本已儲存的版面設定，並留在版面設定 Tab。
- Drag／上移／下移使用共用的欄位排序邏輯，不各自維護不一致的規則。
